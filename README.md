# ForestMerge — объединение фрагментированных лесотаксационных выделов

Трек 3, задача 5. После рубки накладываем контур мероприятия на выдельную сеть, находим «осколки»,
принимаем **обоснованное** решение об объединении (со ссылками на пункты Лесоустроительной инструкции,
Приказ Минприроды № 510 от 05.08.2022) и пересчитываем таксационные характеристики по
**настраиваемым** параметрам. Выход — новая сеть (GeoJSON), ТО в формате образца (XLSX: «Общие»,
«Ярус насаждения», «Подрост» + журнал решений и баланс) и журнал с обоснованиями.

План и анализ данных — [PLAN.md](PLAN.md). Обучение моделей — [docs/TRAINING.md](docs/TRAINING.md).
Развёртывание на https://hakaton.softrush.ru (домен, HTTPS, пользователи, перенос моделей, очистка обучающего сервера) — [docs/DEPLOY.md](docs/DEPLOY.md).

## Быстрый старт (Windows, локально)

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pytest -q                              # 22 теста: ядро, авторизация, проверка загрузки
.venv\Scripts\python -m forestmerge run --sample --out out/sample
.venv\Scripts\python -m api.users add admin --admin          # пользователь для входа (пароль спросит)
.venv\Scripts\python -m uvicorn api.main:app --port 8765       # → http://localhost:8765
```
Для локальной разработки вход можно отключить: `set FM_AUTH=0` (Windows) / `FM_AUTH=0` (Linux).
В браузере: «Открыть образец» → карта с фрагментами → клик по фрагменту → карточка решения.
Docker: `docker compose up --build`.

## Как устроено

```
вход: сеть (GeoJSON) + ТО (XLSX образца / 3 CSV) + лесосеки (GeoJSON) + объёмы заготовки (CSV)
 │
 ├─ io/readers.py     cp1251, «[NULL]», «1 940», десятичная запятая, дубль колонки высоты, итоговая строка
 ├─ geometry.py       UTM, геодезические площади (как в ТО, ±0,03 га), перекрытия лесосек, overlay, граф смежности
 ├─ solver.py
 │   1. техосколки: < 0,05 га или уже 12 м → к соседу из того же выдела (= правка контура лесосеки)
 │   2. единицы: остатки выделов; выдел-вырубка на лесосеку (сплошная; делится по ТЛУ, если части ≥ мин.);
 │      части, пройденные выборочной рубкой (запас минус объём из 5_3 по породам)
 │   3. мелкие (< мин. площади п.196 для категории и разряда) — от меньших к большим:
 │      кандидаты = смежные выделы → жёсткие фильтры (матрица совместимости категорий земель) →
 │      пересчёт объединённого выдела → допуски п.218/п.215 (запас/га, коэфф. состава, полнота,
 │      порода, группа возраста) → стоимость (дистанция по признакам обособления п.233–241, доля общей
 │      границы, компактность, «тот же исходный выдел», «крупнейший сосед») или балл ML-ранжировщика
 │   4. части одного исходного выдела в пределах допусков снова становятся одним выделом; нумерация
 │      (номер у крупнейшей части, новые — после max, с СЗ на ЮВ по п.290)
 ├─ recalc.py         площадь, запасы — суммы; состав — по запасам пород; возраст/H/D — средневзвешенно;
 │                    бонитет — мода по площади; ТЛУ/тип леса — от основного; группа возраста — пересчёт;
 │                    подрост — средневзвешенно; клочок насаждения в вырубке → «запас единичных деревьев»
 ├─ rules.py          п.196, п.215, п.218, п.233–241 — каждая проверка со ссылкой на пункт
 ├─ explain.py        шаблонные обоснования (+ опционально локальная LLM)
 └─ ml_hooks.py       подключение моделей M1–M3 из models/ (необязательно)
```

Все нормы — в [config/norms_2022.yaml](config/norms_2022.yaml) (минимальные площади по разрядам,
допуски по способам таксации, пороги обособления, веса, методы пересчёта, правила совместимости).
Справочник пород (коды НСИ ↔ сокращения ↔ классы возраста) — [config/species.yaml](config/species.yaml),
собран из данных скриптом [scripts/build_species.py](scripts/build_species.py).

## Веб-приложение

FastAPI + статический фронтенд (MapLibre GL с CDN, без сборки):
* вход по логину и паролю (PBKDF2, сессии HttpOnly/Secure, защита от перебора), роли user/admin;
  HTTPS на 443 через nginx + Let's Encrypt — [docs/DEPLOY.md](docs/DEPLOY.md);
* загрузка своих файлов или образца; слои «до / фрагменты / после», лесосеки, подложка OSM/спутник;
* карточка фрагмента: кандидаты-соседи с баллами, допуски ✓/✗ с пунктами ЛИ, текстовое обоснование;
  кнопки «Принять», «Присоединить к выбранному», «Оставить отдельным (п.197)» → пересчёт и **метка для
  дообучения** ранжировщика (SQLite `data/app.db`);
* карточка выдела «после/до», журнал решений с фильтрами, таблица ТО; экспорт XLSX/GeoJSON/JSON;
* панель параметров: разряд, способ таксации, минимальные площади, пороги осколков, веса, методы пересчёта.

API: `POST /api/projects` (multipart) · `POST /api/projects/sample` · `POST /api/projects/{id}/run`
(`{"params": {...}, "use_models": bool, "llm": bool}`) · `GET /api/projects/{id}/result` ·
`POST /api/projects/{id}/decisions` (`{"fragment", "action": accept|merge|keep|reset, "target"}`) ·
`GET /api/projects/{id}/export?fmt=xlsx|geojson|json` · `GET /api/config` · `POST /api/models/reload`.

CLI: `python -m forestmerge run --network сеть.geojson --taxation ТО.xlsx --lesoseki лс.geojson
[--volumes объёмы.csv] [--rank 1] [--params '{"tolerances": {"method": "актуализация"}}'] [--models]`.

## ML (обучение на сервере с RTX 4090)

| | модель | зачем |
|---|---|---|
| M2 | CatBoost-импутация H/D/возраста | пропуски в ТО 18–29 %; уже на CPU MAE −38…−64 % к базлайну |
| M1 | трансформер-энкодер выдела (masked modeling) | эмбеддинг «похожести выделов» как признак |
| M3 | LightGBM LambdaRank | выбор соседа: дистилляция учителя-перебора + дообучение на правках специалистов |
| M4 | (опц.) Qwen 7B QLoRA / RAG | текст обоснования для пояснительной записки |

Пошагово — [docs/TRAINING.md](docs/TRAINING.md).
